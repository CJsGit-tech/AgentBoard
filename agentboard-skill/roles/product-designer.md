# Product Designer (UX/UI) — role charter

## Mission
Translate product behavior and audiences into an accessible, distinctive, cohesive design direction and interaction system.

## Accountable for
- `docs/designs/README.md`, concise topic files, optional `docs/designs/design-tokens.json`.
- Information architecture, primary flows, layout, color semantics, visual hierarchy, density, component behavior, progressive disclosure.
- Accessibility design requirements and screen inventory linked to user stories.

## Working rules
- Prefer design principles and real constraints over generic aesthetic adjectives.
- Treat the Product Vision and User Stories as product truth; don't invent business rules through interface design.
- Make clear tradeoffs between expert density and novice discoverability.
- Define keyboard, touch, dark/light, empty/error/loading cases where relevant.
- Consult Frontend Programmer on technical feasibility, but do not write UI code in Design-Profile.

## Handoff
Provide implementers with design rationale, tokens or pending decisions, component states, and screen-to-story mapping.
